# OpenKart Divergences Log

Every behavioral or architectural divergence from pinned upstream **SuperTuxKart `1.5`** (`supertuxkart/stk-code`, commit `1fb491f507216c5d181ccd85f29ff08eca003827`) is recorded here with its cause (`engine limit`, `platform policy`, or `ToS`).

---

## Accepted Architectural Divergences (`AGENTS.md`)

| Area | Upstream STK `1.5` | OpenKart Behavior | Cause |
|---|---|---|---|
| **Vehicle Physics Solver** | Bullet Physics (`lib/bullet` + `src/physics/btKart.cpp`) raycast vehicle with bilateral zero-slip tire constraint (`<friction slip="10000000"/>`) and colliding `btCompoundShape` chassis rigid body + contact manifold. | Pure-Luau 120 Hz fixed-step rigid-body + 4-wheel raycast solver ([physics-spec.md](physics-spec.md)) with Pacejka slip-angle → grip curve; **Bullet contact-manifold & swept CCD replaced by unified resting-contact manifold (wheel bottom-out + static `GetPartBoundsInBox` overlap recovery + 6-axis shrunk-core probes + post-rotation overlap guard) and swept `Workspace:Blockcast` via `WorldQuery` with normal velocity projection** (measurable delta TBD against STK `1.5` reference telemetry). | **Engine limit** — C++/Bullet native runtime cannot execute on Roblox; deterministic Luau solver also required for exact state-reset + input-replay reconciliation. |
| **Networking & Synchronization** | ENet peer-to-peer / LAN host with global `RewindManager` state rollbacks (`src/network/`). | Server-authoritative Roblox match loop (`8–20` players) over `RemoteEvent` / `UnreliableRemoteEvent` with client-side input prediction/reconciliation and remote interpolation. | **Engine limit / platform policy** — Roblox controls transport, sockets, and server-client trust boundaries. |
| **Track & Kart Addons** | Runtime dynamic download & mounting of `.zip` addon packs (`src/addons/`). | Offline-converted curated packs built into the place via `tools/stk2rbx` and audited per-file in [CREDITS.md](../assets/CREDITS.md). | **Platform policy** — Roblox prohibits arbitrary dynamic code/asset loading at runtime. |

| **Resting-Contact Restitution Threshold (`restContactBounceVel = 2.0 m/s`)** | OpenKart uses STK's exact speed-dependent piecewise-linear wall restitution curve (`0:1.0, 5:1.0, 20:0.2`, `data/stk_config.xml:L480`, `src/karts/kart.cpp:L1454`). In Bullet (`lib/bullet/src/BulletDynamics/ConstraintSolver/btContactSolverInfo.h:L82`), `m_restingContactRestitutionThreshold = 2` suppresses bounce on persistent resting contacts by contact lifetime in ticks. | **Engine limit / solver design** — OpenKart's stateless swept/overlap manifold does not persist contact-point lifetimes across ticks, so it suppresses bounce for normal impact speeds `< 2.0 m/s` (`KartTuning.collision.restContactBounceVel`) to prevent wall chatter while preserving STK restitution on dynamic impacts. |
| **Static Kart Mesh First Pass (Driver/Steering Animation Omitted)** | Upstream `stk-assets/karts/tux/tux.spm` is a skinned `SPMA` mesh (`16` bones, `60` keyframes over frames `0..613`, `m_bind_frame = 20`) driven by `KartModel::update` (`src/karts/kart_model.cpp`) for steering lean (`0..20..40`), win/lose/jump cycles, and bone-attached accessories (`headlight.spm`, `hat`). OpenKart's first-pass kart emitter (`tools/stk2rbx/kart_emit.py`) exports only the static pre-computed straight-pose (`frame 20`) `Body` + `Driver` `.glb` meshes plus 4 separate rigid wheel meshes (`WheelFrontLeft/Right`, `WheelRearLeft/Right`). | **Engine limit / phased pipeline** — Roblox requires a glTF/FBX skinned `Bone` + `AnimationClip` export pipeline (or runtime joint transforms) rather than STK's `SPMA` binary format. Skeletal driver/steering lean and night-only `headlight.spm` (external un-audited textures) are omitted in the first pass and deferred until rigged `.glb` export and `src/client/kart/KartPresentation.lua` land. |
| **Gated Server Powerup Roll Table (`ItemTuning.IMPLEMENTED_POWERUPS`)** | Upstream `PowerupManager::getRandomPowerup` rolls across all `10` powerup weights from `data/powerup.xml` (`bubblegum`, `cake`, `bowling`, `zipper`, `plunger`, `switch`, `swatter`, `rubberball`, `parachute`, `anvil`). Unfiltered `data/powerup.xml` and gated 10,000-roll distributions are verified in `tests/Items.spec.luau` and `tests/Flyable.spec.luau`. |
| **Rigid-Part Attachment Placement (`parachute`, `plunger` face)** | Upstream `Attachment` mounts `parachute.spm` and `plunger.spm` dynamically to runtime kart/track sockets and skeletal poses. OpenKart converts `.spm` assets as static straight-pose meshes without runtime `Bone` sockets (`docs/kart-spec.md`). | **Rigid-part mesh import boundary** — `Attach_parachute` mounts at kart origin using `parachute.rbxmx` vertices centered around `(0, +0.57436, +0.87352)` studs (`ImportFlipY180 = true`); `Attach_plunger_face` mounts rigidly at `(0, 0.58, -0.62)` studs (unflipped so `+Z` suction cup meets Tux's face) relative to `Head` socket `(0, 0.690, +0.030)` (`kart.xml:L50-L53`) alongside the 2D `plungerface.png` HUD overlay (`GameHud.client.lua`). |
| **`supertuxkart.net/Powerups` Wiki vs. Pinned STK `1.5` Source Conflict (`Bubblegum` Shield vs. Squash)** | The public web wiki page `https://supertuxkart.net/Powerups` states *"The bubblegum shield doesn't protect against [basketball] squashing."* Pinned STK `1.5` source (`src/items/rubber_ball.cpp:L870` calling `Kart::setSquash` at `src/karts/kart.cpp:L1866-L1870`) executes `if (isShielded()) { decreaseShieldTime(); return false; }` before applying squash. | **Pinned upstream source authority (`AGENTS.md`)** — OpenKart follows pinned STK `1.5` source (`KartSolver.applySquashHit` pops an active bubblegum shield rather than squashing the shielded kart). |
| **Nitro Activation Gate (`accel > 0` & `isOnGround`)** | Upstream `Kart::updateNitro` (`src/karts/kart.cpp:L2244-L2302`) checks only `m_controls.getNitro() && m_min_nitro_ticks <= 0 && m_collected_energy > 0`, without requiring throttle (`accel > 0`), and allows starting `m_min_nitro_ticks` while airborne (draining energy without `increase_speed` until grounded). OpenKart gates initial nitro activation and post-64-tick hold continuation on `accel > 0 and isOnGround` (while letting any already-committed 64-tick burn finish cleanly if throttle is released mid-burn), and dims the HUD nitro gauge when the gate is closed (`nitroEnergy > 0`, not burning, and not `(accel > 0 and isOnGround)`). | **Intentional playability divergence** — Prevents accidental zero-throttle / mid-air nitro energy waste when pressing `N` while parked or jumping, while preserving STK's 64-tick minimum burn commitment once triggered. |
| **Pure-Math Pairwise Kart-Kart Collision (`resolveKartKartCollisions`)** | Bullet resolves kart-kart rigid body contacts in 3D via `btSequentialImpulseConstraintSolver`, and `Physics::KartKartCollision` (`src/physics/physics.cpp:L438-L558`) adds the `3000 N` (`0.1 s`) timed central push. | **Accepted engine divergence (`AGENTS.md`)** — OpenKart resolves pairwise kart overlaps in pure Luau (`KartSolver.resolveKartKartCollisions`, 2D XZ OBB SAT + mass-weighted normal restitution exchange + `Physics::KartKartCollision` timed push + bomb pass) sorted deterministically by kart `id` with zero `Workspace` queries so server authority and client replay remain bit-identical. |
| **Speed-Scaled AI Lookahead Rule (`AIController.selectLookaheadPoint`)** | Upstream `SkiddingAI::findNonCrashingPoint` (`src/karts/controller/skidding_ai.cpp:L2695-L2774`) steps forward quad-by-quad until a sharp turn or road-edge chord violation. | **Phased implementation scope** — `AIController.selectLookaheadPoint` retains the upstream `1.5 rad` sharp-curve early break (`skidding_ai.cpp:L2725`) and `steerToPoint` circular-arc pursuit (`ai_base_controller.cpp:L86-L150`), using continuous speed-scaled lookahead `L(v) = clamp(|v| * 0.65, 6.0, 28.0)` along `drivelineQuadCenters` until full `DriveGraph` quad path-width ray marching is ported. |
| **Gamepad Deadzone (`0.15`) & Deferred Multitouch Options** | `src/input/device_config.cpp` omits a deadzone constant (`src/input/gamepad_config.cpp:L64` sets `m_deadzone = 4096`, i.e., `4096 / 32768 = 0.125`), and `src/states_screens/race_gui_multitouch.cpp` / `src/config/user_config.hpp:L366-L590` support accelerometer tilt steering, gyroscope steering, auto-acceleration, and screen rotation. | **Phased implementation scope** — `InputMapper.GAMEPAD_DEADZONE` uses `0.15` for Roblox `Thumbstick1` polling (`GetGamepadState`). On-screen touch controls (`TouchControls.lua`) implement the steering wheel + action buttons layout; tilt steering (accelerometer/gyroscope), auto-acceleration, and screen rotation are deferred. |
